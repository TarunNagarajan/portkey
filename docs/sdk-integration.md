# SDK distribution and integration example

The root application remains a private npm package. The standalone, dependency-free SDK package in `sdk-package/` exposes the backend client at `portkey` and the callback helper at `portkey/browser`. Build and pack it from the repository root with `npm run sdk:pack` (equivalent to `npm run sdk:build` followed by `npm pack ./sdk-package`). The tarball contains the compiled SDK JavaScript, declarations, package metadata, and package README. The Node entry requires Node.js and must stay in backend code. The browser entry only reads `code`, `state`, or `error` from the callback URL fragment, removes that fragment from browser history immediately, and returns the parsed values.

`examples/relying-party` is the runnable reference integration. It uses the actual packaged SDK, PostgreSQL-backed Express sessions with a ten-minute lifetime, exact configured origin and callback values, CSRF and Origin checks, and a unique session/flow claim committed before network exchange. The example's `DATABASE_SCHEMA` setting isolates its session and claim tables when sharing a PostgreSQL server. Follow its README for setup. Create the SDK tarball from the repository root first; the example's package file reference points to that tarball, so this does not require a registry publish or install of the root application's dependencies.

The production app key, verifier, state, and pending request metadata belong in server-side storage. Never embed the API key in browser code or send the verifier in a URL. A callback should only be accepted for the app session that initiated the request, and its flow must be claimed atomically before exchanging the one-use code. Configure an exact registered callback URL and pin the expected contract ID, version, and digest in server configuration.

The root README's verification platform section links to this guide and to the [standalone example setup](../examples/relying-party/README.md). The example's local package file reference expects the tarball created from the repository root; no registry publish is required.
