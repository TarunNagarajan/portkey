# Demonstrate Portkey

From the repository directory, run `npm ci`, then `npm run platform:demo`. Keep the process running. It builds the application and starts an isolated local Portkey instance and two independent relying applications. The terminal prints the application addresses and a one-use organizer setup link. Keep that setup link private: it grants control of the sample issuer workspace.

Use a separate browser profile for the demo organizer, then open the organizer setup link there. This keeps the demo's local login separate from your development login. Claiming a new demonstration workspace signs this browser out of a previous demo organizer account. On **Account**, explicitly adopt the new sample workspace and create a passkey. Save the recovery key somewhere private. The demonstration group and contract now belong to that organizer account. This step requires a browser and device that support passkeys.

Create a room with **Workshop credential + proof** admission. In its admission source, select **Reusable credential groups**, choose **Portkey demonstration members**, and save the rule. Enable the encrypted inbox and save an encrypted key backup with its passphrase. Open the room and copy the invitation generated by the organizer browser; it includes the trusted inbox key fingerprint.

Use a separate browser profile or private window for the participant. Open Northstar Learning at `http://northstar.localhost:5301`, choose **Get the issuer’s demo enrollment link**, and save the credential in that participant browser. Return to Northstar, choose **Continue with Portkey**, review the request, prove membership and return to the application. Repeat the membership check at Fieldnote Community, `http://fieldnote.localhost:5302`, in the same participant browser. Both backends verify separate requests using the one saved credential.

Open the room invitation in the participant browser, present the saved credential and enter. Upload a small file. In the organizer browser, open the inbox and download the submission. The file should match the original; its contents and filename were encrypted in the participant browser and decrypted in the organizer browser.

The sample issuer is fictional and its group is intentionally small. This demonstrates eligibility checks and encrypted submissions, not real-world identity or anonymity. Keep participant and organizer profiles separate throughout the demonstration. Clearing participant site data loses its credential; organizer account recovery does not restore inbox keys. Keep the encrypted key backup separately.

Stop the launcher with Ctrl+C. These addresses work on this computer only. For a phone demonstration, follow the HTTPS setup in the main README; do not send a phone one of these loopback addresses. A real phone check must be performed separately.
